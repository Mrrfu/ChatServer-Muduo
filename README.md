# Cpp-ChatServer
基于`libevent`的封装的轻量级C++聊天服务器。
    
### 网络模块

在`ChatServerLib.cc` 使用 libevent 库实现了一个异步 TCP 服务器。主要工作流程如下：
#### 1. 服务器初始化（构造函数）
- **创建事件循环**：`event_base_new()` 创建一个事件循环句柄 `_base`，用于管理所有 I/O 事件。
- **构造监听地址**：使用 `sockaddr_in` 结构体设置 IPv4 地址和端口（通过 `inet_pton` 和 `htons`）。
- **绑定监听器**：`evconnlistener_new_bind()` 在指定 IP 和端口上创建监听器 `_listener`。
  - 绑定到 `_base`，设置回调 `acceptConnCb`，上下文为 `this`。
  - 标志 `LEV_OPT_REUSEABLE` 允许地址重用，`LEV_OPT_CLOSE_ON_FREE` 在释放时自动关闭套接字。
- **错误处理**：如果监听器创建失败，输出错误信息。

#### 2. 启动服务器（start() 方法）
- **进入事件循环**：`event_base_dispatch(_base)` 启动事件调度循环。
  - 循环监听所有注册的事件（包括监听器和连接）。
  - 阻塞等待事件发生，处理完成后继续循环。
  - 服务器的核心运行状态，直到手动停止或出错。

#### 3. 处理新连接（acceptConnCb 回调）
- **触发条件**：当客户端连接到服务器端口时，libevent 自动调用此静态回调。
- **恢复上下文**：将 `ctx` 转换为 `ChatServerLib*` 指针。
- **创建 bufferevent**：`bufferevent_socket_new()` 为新套接字 `fd` 创建缓冲事件对象。
  - 关联到 `_base`，标志 `BEV_OPT_CLOSE_ON_FREE` 确保释放时关闭套接字。
- **定义消息回调**：`onMessage` lambda 函数处理接收到的数据。
  - 解析 JSON，获取消息处理器，调用 `ChatServiceLib` 的业务逻辑。
- **定义关闭回调**：`onClose` lambda 函数从连接表移除连接。
- **创建 Connection 对象**：`Connection::create()` 封装 bufferevent 和回调。
  - 返回 `shared_ptr<Connection>`，由服务器管理生命周期。
- **保存连接**：使用互斥锁将连接存入 `_connMap`（按 fd 索引）。

#### 4. 数据处理和连接管理（Connection 类）
- **读事件**：当有数据到达时，`Connection::readCb` 被触发。
  - 从输入缓冲区读取数据，解析为字符串。
  - 调用 `onMessage` 回调，传递给 `ChatServiceLib` 处理业务逻辑。
- **事件处理**：`Connection::eventCb` 处理连接状态变化。
  - 检测 EOF、错误、超时等事件。
  - 调用 `onClose` 回调，从 `_connMap` 移除连接。
  - 释放 bufferevent 资源。
- **发送数据**：通过 `Connection::send()` 将响应数据写入输出缓冲区。

#### 5. 服务器关闭（析构函数）
- **释放资源**：`evconnlistener_free(_listener)` 和 `event_base_free(_base)` 清理监听器和事件循环。
- **连接清理**：所有 `Connection` 对象通过 `shared_ptr` 自动释放。

#### 技术要点
- **异步非阻塞**：所有 I/O 操作通过事件循环处理，无需多线程。
- **资源管理**：使用 `shared_ptr` 和 `weak_ptr` 管理连接生命周期，避免内存泄漏。
- **线程安全**：通过互斥锁保护共享的 `_connMap`。
- **扩展性**：业务逻辑通过回调解耦，便于添加新功能。

### 服务器端业务功能

1. 软件设计按照分层设计，分为三层： 业务层、数据层、表现层。业务模块需要和数据操作模块分开，尽量解耦合。不能在业务层中出现对数据库操作的代码（增删查改）。
2. 为提高并发能力，还支持服务器集群部署。使用Nginx作为反向代理，接受客户端的请求并根据设置的分配算法转发至某台服务器。服务器处理后将消息发送至Nginx，再发送至客户端。

### 客户端功能

客户端支持单人实时聊天和多人实时聊天。

- 具体功能有：添加好友，加入群组，创建群组。
- 客户端使用两个线程：读线程和写线程。
  - 读线程专门接受从服务器发送的数据，写线程用于将客户端数据发送至服务器。
  - 两个线程之间的通信用信号量进行（sem_t），注意只能在 Linux 使用（跨平台可以替换为 C++20 的信号量）。当创建 socket 成功后启动一个子线程作为读线程，接受用于处理后续的登录、注册、创建群组业务的返回信息以及聊天信息。

### 分布式部署
- 使用nginx作为tcp负载均衡器,根据设定的算法选择将消息发送至某台服务器。
  - 负载均衡算法有：普通轮询、加权轮询、随机选择。本项目使用轮询。


- 跨服务器通信使用基于订阅-发布的redis消息队列。
  - 用户在登录成功后，服务器端在消息队列中订阅用户id，用于接受其他服务器转发消息。
  - 服务器收到消息后，先检查本地保存的用户连接路由表有没有当前用户的连接，如果有直接发送消息；如果没有先检查是否在线，如果在线则向消息队列发布消息，否则将向数据库写入离线消息。

## 编译
```shell
cd build

cmake ..

make
```
生成的可执行文件在bin目录下。
